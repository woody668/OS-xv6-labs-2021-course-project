# Util 实验记录

## 实验目的

本实验通过实现五个 xv6 用户程序，熟悉 xv6 用户态接口、系统调用使用方式、进程创建与回收、管道通信、目录遍历以及 `fork-exec-wait` 执行模型。

## 实验环境

- Windows 11 + WSL 2
- Ubuntu 20.04
- QEMU RISC-V 模拟器
- RISC-V GNU 交叉编译工具链
- MIT xv6-labs-2021 `util` 分支

## 实验内容

| 程序 | 主要功能 | 涉及机制 |
| --- | --- | --- |
| `sleep` | 按指定 tick 数暂停进程 | 参数解析、`sleep` 系统调用 |
| `pingpong` | 父子进程双向传递一个字节 | `fork`、双管道、文件描述符继承 |
| `primes` | 使用进程管道实现并发素数筛 | 递归进程链、管道、EOF 传播、进程回收 |
| `find` | 在目录树中递归查找指定文件 | 目录项、`fstat`、路径拼接、递归遍历 |
| `xargs` | 将标准输入转换为命令参数并逐行执行 | 标准输入、参数数组、`fork-exec-wait` |

## 关键实现说明

### sleep

检查命令行参数数量，通过 `atoi` 将 tick 参数转换为整数，然后调用 xv6 已有的 `sleep` 系统调用。参数错误时向标准错误输出用法并以非零状态退出。

### pingpong

建立两条单向管道分别承担父进程到子进程、子进程到父进程的数据传递。`fork` 后双方关闭不使用的管道端，避免无效引用影响管道生命周期。

### primes

主进程向管道写入 2 到 35。每级筛选进程读取第一个数作为素数，创建下一级管道和子进程，并将不能被当前素数整除的数字继续传递。写端关闭后，EOF 沿进程链传播，各级进程依次退出并由父进程回收。

### find

使用 `open` 和 `fstat` 判断路径类型。目录路径通过读取 `struct dirent` 遍历，跳过 `.` 与 `..` 后递归处理子项；普通文件则比较路径最后一个分量与目标名称。

### xargs

从标准输入逐字符读取一行，按空格和制表符切分附加参数，与原命令参数共同组成新的 `argv`。每读取一行便创建子进程执行目标命令，父进程等待完成后继续处理下一行。

## 手动验证

在 QEMU 启动的 xv6 Shell 中依次验证：

```text
echo before-sleep
sleep 20
echo after-sleep
pingpong
primes
mkdir lab1check
echo hello > lab1file
echo hello > lab1check/lab1file
find . lab1file
find . lab1file | xargs grep hello
```

验证结果：`sleep` 能够在指定时间后正常返回；`pingpong` 完成双向通信；`primes` 输出 2 到 31 的全部素数；`find` 找到根目录和子目录中的两个同名文件；`xargs` 对两个文件分别执行 `grep` 并输出两行 `hello`。正式手动运行截图与自动评分截图保存在课程项目的 `素材/1` 目录中。
